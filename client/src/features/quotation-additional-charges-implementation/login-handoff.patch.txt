GUEST LOGIN HANDOFF — MERGE INTO YOUR EXISTING EXPORTER LOGIN FLOW

PublicQuotationPage now sends these request fields in `location.state.quoteHandoff` for a guest:
- quoteId
- selectedQuoteItemIds
- customsChargeRequested
- invoiceValue (only when customs was requested)
- invoiceCurrency (only when customs was requested)
- transportChargeRequested
- customerMessage (only when provided)

After the login page has authenticated the exporter, ensure its existing quote-handoff handler posts every field to the existing submission API. Do not just send selectedQuoteItemIds or the additional choices/note will be lost.

Illustrative merge (adapt to your existing state types/API imports; do not add a second login flow):

const handoff = location.state?.quoteHandoff;
if (user?.role === "EXPORTER" && handoff?.quoteId) {
  const submission = await submitPublicQuoteRequest(handoff.quoteId, {
    selectedQuoteItemIds: handoff.selectedQuoteItemIds,
    customsChargeRequested: handoff.customsChargeRequested === true,
    ...(handoff.customsChargeRequested === true
      ? { invoiceValue: Number(handoff.invoiceValue), invoiceCurrency: handoff.invoiceCurrency }
      : {}),
    transportChargeRequested: handoff.transportChargeRequested === true,
    ...(typeof handoff.customerMessage === "string" && handoff.customerMessage.trim()
      ? { customerMessage: handoff.customerMessage.trim() }
      : {}),
  });
  navigate(`/exporter/quotations/${encodeURIComponent(submission.id)}`, { replace: true });
}

The PublicQuotationPage implementation already submits directly when `useAuthStore()` indicates the current user is an EXPORTER. This login handoff is only for visitors who were not logged in when they created the quote.
